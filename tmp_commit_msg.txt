Fix localStorage clear + add 'Flag: Also clear current work' toggle

### Fixed
*   `src/context/FlowContext.tsx` — `clearLocalStorage` no longer just
    removes `flowonline2_program` and silently lets the debounced
    500ms save resurrect the cleared state. The new implementation
    also cancels any pending debounced save timeout, synchronously
    overwrites `latestSaveRef.current` with the empty-state tuple, and
    cleans up the additional `flowonline2_author`,
    `flowonline2_mobile_view`, `flowonline2_autosave` keys when the
    user opts in.
*   The fix is structured in two phases split across the `try/catch`
    boundary so a failed localStorage write (private-mode browser,
    quota exceeded) leaves the user's in-memory chart UNTOUCHED
    rather than half-cleared. Phase A: storage + ref updates in try.
    Phase B: state setters OUTSIDE try. Either both phases run, or
    the catch returns early with only a console.warn.

### Added
*   **'Flag' toggle in the mobile clear-localStorage dialog
    (`src/mobile/MobileToolsView.tsx`).** Off by default. When the user
    activates it, `clearLocalStorage({ alsoClearCurrentWork: true })`
    is called: the dialog emoji pill + accent-red border highlight
    the destructive intent; the toast confirms with "localStorage
    fully cleared ✓ (including current work)"; the in-memory canvas
    is fully reset.
*   **Default behavior is preserved.** The desktop menu at
    `src/components/Header.tsx:2123` still calls `clearLocalStorage()`
    with no args, hitting the backward-compatible default branch
    that ONLY removes `flowonline2_program` — the user's
    in-progress work continues to autosave to the legacy slot. No
    call-site updates were required.

### Architecture invariants (still held)
*   tsc --noEmit clean, npx vitest run 126/126 passed.
*   Single source of truth for "clear storage" lives in
    `FlowContext.clearLocalStorage` — future localStorage keys
    (layout, colorScheme, etc.) should be added there, not at
    every call site.
*   The mobile `MobileToolsView.handleClearLocalStorage` no longer
    manually `localStorage.removeItem('flowonline2_autosave')` —
    that key is now removed centrally inside FlowContext when the
    flag is on.
